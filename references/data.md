# 用户目录、外链库和其他数据

这个文件管数据放在哪、每个字段什么意思、谁来填谁能改：SKILL 默认档案和用户档案怎么分、用户目录里有什么、外链库、竞品专属库、所属行业这条线。提交资料（profile.json）和提交台账（ledger.json）的字段见 submit.md「准备」和「每个外链网站怎么做」。名词见 SKILL.md「名词」。

## SKILL 默认档案和用户档案

- **SKILL 默认档案**（在 SKILL 目录里，作者给的，所有用户一样）：`scripts/` 程序、`references/` 规则文档、`assets/library/` CCG 外链库、`assets/report/` HTML 报告模板、`assets/templates/` 用户目录和独立站的模板。SKILL 目录里没有任何用户的东西（SKILL.md「原则」第 2 条），SKILL 更新、整个删掉重装都不丢用户档案。
- **用户档案**（在用户目录里，每个用户自己的）：独立站资料、提交台账、用户外链库、分析结果（含竞品专属库和日志）、报告。

## 用户目录

位置记在电脑用户文件夹的 `.seo-external-link.json`（Windows 是 `C:\Users\<用户名>\.seo-external-link.json`，Mac 是 `/Users/<用户名>/.seo-external-link.json`），不在 SKILL 目录里。第一层只放给用户看的报告网页和说明，中间文件都收进 `data/`。

```
<用户目录>/
├── 外链报告.html                HTML 外链报告，双击打开看（菜单 5、6 生成；菜单 10 的网页打开、刷新就是最新数据）
├── 用户档案说明.txt            告诉用户这里都是他的资料、要备份、只存在本地（菜单 6 从模板拷）
└── data/                       程序自己用的数据，用户不用管
    ├── report/                 报告网页用的样式、脚本和数据（菜单 5、6 生成）
    ├── settings.json           用户设置
    ├── update_notes.json       报告右上角的更新备注（AI 写，见 report.md）
    ├── dataforseo.txt          DataForSEO 账号（菜单 6 拷一份空的，用户要挖竞品外链时自己填）
    ├── library/                用户外链库（usable_sites.jsonl、unusable_sites.jsonl）
    ├── sites/<独立站域名>/      profile.json 提交资料（含所属行业）、ledger.json 提交台账、logo 和截图
    └── analyses/<分析结果目录>/  每查一次竞品一个：raw/ 原始数据、results.json、reviews.json、
                                industries.json 这批外链网站的所属行业、
                                competitor_library.json 竞品专属库、log_<时间>.log 日志
```

- **第一次用**：程序报「还没设置用户目录」时先做 setup.md「基础工作准备」，用户给了文件夹路径再做 setup.md「建用户目录」（菜单 6）。
- **新建独立站**：跑菜单 7（第二行：独立站域名），会建 `data/sites/<域名>/profile.json`（从模板拷，自动生成发外链密码）。发外链邮箱照 accounts.md「发外链账号」找用户要，其余提交资料照 submit.md「准备」填。
- **settings.json**：`current_site` 当前发外链的独立站（整理结果时免费类外链网站进它的台账，换独立站就改这里）；`default_target` 菜单 1 直接回车查的竞品；`dataforseo_env_file` DataForSEO 账号文件（里面写「DataForSEO_API_login=」「DataForSEO_API_password=」两行，老的 DATAFORSEO_USERNAME / DATAFORSEO_PASSWORD 写法也认），空着就用 `data/dataforseo.txt`。账号由用户自己填进文件，AI 不在对话里收、不打印。
- **日志**：菜单 1～4 的日志写进那一批分析结果目录（菜单 1 查多个目标时，每个目标的日志进各自的目录）；菜单 5～10 只在屏幕上打印。

## 外链库

结论按外链网站给：页面逐个查，但一个外链网站只要有一个页面是免费类，整个外链网站就是免费类（留一个链接只要一个入口）；否则有无法判断的还要复核；再否则付费类；所有页面都不可用才算不可用。竞品专属库、日志、复核清单都按外链网站列。

每层外链库两个文件，一个外链网站一行（JSONL）：`usable_sites.jsonl` 放可用的（免费类、付费类），`unusable_sites.jsonl` 放明确不可用的。

```json
{"site": "aiknow.cc", "verdict": "免费类", "industry": "AI产品工具", "paid_option": null, "group": "直接提交", "site_type": "导航与产品发布类", "scope": "整站", "how": "怎么发外链", "entry_url": "提交入口", "check": "收录条件或要人确认的", "reason": "依据", "source": "提交实测", "checked_at": "2026-10-24", "first_seen": "2026-10-23", "domain_rank": 21, "dofollow": true, "noindex": false, "ccg_id": "ccg-0001"}
```

- **ccg_id CCG 编号**：CCG 外链库每行一个，格式 `ccg-` 加四位数字，一个外链网站一个号，永远不变（换文件、改结论都不改）。只有作者往 CCG 外链库加新外链网站时才编新号（接着最大的号往下编）；从 CCG 外链库抄进用户外链库的行原样带着，用户自己新增的外链网站留 null。

- **industry 所属行业**：每个外链网站都要有（不可用的也要），判法见 criteria.md「所属行业」。自动预判不判行业，由 AI 判了写进 industries.json，整理结果时并进来（见「所属行业：从挖掘到发外链」）。
- **group 发外链方式、site_type 业务类型**：免费类才有，定义和取值见 criteria.md「免费类再分两个维度」。group 只有「直接提交」「注册账号提交」两种；site_type 四种（要挂回链或徽章 / 导航与产品发布类 / 社区论坛类 / 自建类），装不下的先问用户要不要加新类型，没点头就留 null。
- **scope 结论范围**：整站 = 对整个外链网站成立（提交规则、收费档、平台类型），以后再碰到直接用；页面 = 只在某些页面上看到（评论关了、编辑文章、页面没了），以后碰到这个外链网站的别的页面还要重查；碰到的是以前人工复核过的同一个页面（以前分析结果目录 reviews.json 里用页面网址做键的那条），脚本默认直接用那条结论。
- **source 来源**：提交实测 > 人工复核 > 自动预判。人工复核 = 第2、3步在浏览器里看过的结论，不管是 AI 还是用户看的。脚本整理结果时自动把自动预判和人工复核的结论并进用户外链库：低的不覆盖高的，页面范围不覆盖整站范围，无法判断的不进库。
- **domain_rank**：DataForSEO 的域名权重（0–100，取看到过的最高值），整理结果时脚本自动补。
- **dofollow**：在这个外链网站上留的链接是不是 dofollow（true / false，没记录是 null；ugc、sponsored 也算 nofollow；只给纯文本、不是链接的也记 false，reason 写「只给纯文本，不是链接」）。谁来填、谁能改，全 SKILL 只按这两条：
  - 自动的只填空：整理结果时脚本拿竞品链接的属性（脚本打开网页看到的，看不到就用 DataForSEO 给的）填进去，只在空着时填，不改已有的值。
  - 人看到的直接改：任何一步 AI 或用户在浏览器里亲眼看到的（第2、3步复核、第5步核对、第6步回访），跟外链库不一样就改。回访看到的是我们自己的链接，以它为准。
- **noindex**：在这个外链网站上，冷门产品的同类页面（和竞品外链所在页是同一种页面）会不会被禁止谷歌收录（true / false，没记录是 null）。热门产品的页面能收录、冷门的不给收录的外链网站，我们的新独立站一开始就是冷门。谁来填、谁能改，全 SKILL 只按这两条，其他步骤都不写：
  - 第5步提交前只填空：轮到它提交、noindex 还空着时查一次（做法见 submit.md「发外链原则」第 6 条）；已经是 true / false 的不查。
  - 第6步回访直接改：看到我们自己的页面有没有 noindex，跟外链库不一样就改，以它为准。
  - false 必须是亲眼查到能收录；没查到、找不到冷门的同类页面，一律留 null，不猜。
- **paid_option 付费档**：免费类外链网站另有付费档（付费加速、推广位、付费套餐）时写价格和内容，没有就 null。找免费的看 verdict 是免费类；找收费的看 verdict 是付费类，或者 paid_option 有内容。自己的结论和网友经验（比如 web.cafe 投票）在免费、收费上对不上时，不互相否定，记成免费类 + paid_option 两边都算。
- **只写外链网站本身的事实**：「独立站不符合收录范围」「刚上线的独立站先跳过」这类跟独立站有关的原因只写在提交台账；外链网站是从哪个竞品挖出来的看分析结果目录（报告里会算）；独立站有没有被收录看提交台账。外链网站会变，提交前还要再打开看一眼，跟库里不一样就更新。
- **核对完要做的**：每核对完一个外链网站（第2、3步复核，第5步提交或跳过），把它本身的情况写进用户外链库，source 写人工复核或提交实测，checked_at 写核对日期，how 写清楚怎么发，group、site_type、industry 跟实际不符就改、空着就填上。
- **怎么改外链库**：只改用户外链库，CCG 外链库不动（作者维护）。这个外链网站在用户外链库里有，就直接改那一行；只在 CCG 外链库里有，就把那一行原样抄进用户外链库的同名文件再改。结论从可用变不可用时，在用户外链库里把这行挪到另一个文件。

## 竞品专属库

每分析一次竞品的外链出一个文件，放在那一批的分析结果目录里：`<分析结果目录>/competitor_library.json`。它是这批外链网站的处理清单，每次整理结果时脚本整行刷新，不手改：

- `batch`：竞品、这批外链的拉取时间（batch_at）、当时发外链的独立站（independent_site）、外链数、页面数、外链网站数。
- `sites`：一个外链网站一行，写结论、所属行业（industry）、对当前独立站的赛道关系（track）、分组、范围、来源、以前有没有看过（seen_before）、代表页面、处理方式（handling）。
- 处理方式全由脚本按结论和当前独立站的台账算：待复核 / 不可用，不处理 / 台账：<台账状态>（免费类整理结果时已自动进台账，正常都是这个）/ 付费，先问用户要不要做 / 免费，待加入台账（兜底，免费但还没进台账时才出现）。
- 付费类问过用户后，决定记进台账（要做记待提交，不做记跳过，见 submit.md），下次整理结果时这里变成「台账：<状态>」。换个竞品再碰到这个外链网站，台账里已经有决定，不用再问。
- 每次整理结果时，日志会打印还没处理完的外链网站数（处理方式是「待复核」或「免费，待加入台账」的）。整批什么时候算做完，看 submit.md「完成边界」。

## 所属行业：从挖掘到发外链

原则：先做跟独立站契合赛道的外链；其他赛道的先给用户看、用户定了才做（先后细则见 submit.md「发外链原则」）。所属行业贯穿整条线：

1. **独立站**：准备 profile.json 时 AI 按独立站首页定 `industry`，告诉用户定成了什么。没定的，整理结果时日志会提醒，赛道关系算不出来。
2. **挖掘（第1、2步）**：程序不判行业。第1步和每次整理结果的日志最后打印「所属行业还没标的外链网站」清单（外链网站 | 结论 | 页面标题），外链库里已有行业的不列。第2步 AI 按 criteria.md「所属行业」逐个判，判一批存一批，写进这批分析结果目录的 `industries.json`：

```json
{"example.com": "AI产品工具", "forum.example.org": "综合论坛博客"}
```

3. **入库（第4步）**：整理结果时 industries.json 的行业并进用户外链库（写进去的会覆盖库里原来的行业，用来更正）；无法判断的外链网站不进库，行业先留在 industries.json，等它有了结论再整理一次就补上。台账每行的 industry 跟外链库同步，竞品专属库每行带 industry 和对当前独立站的赛道关系（track）。日志按发外链原则打印当前独立站台账「待提交」各档的数量。
4. **发外链（第5步）**：按 submit.md「发外链原则」一档一档发。
5. **报告**：外链库部分有行业组成（按行业、按赛道大类）和按行业筛选；各独立站部分按赛道关系统计外链库里的免费类申请了多少、还剩多少，按发外链原则的档展示台账和外链库里还没发的免费类，清单按档排、带赛道关系。
